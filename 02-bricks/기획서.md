# 벽돌깨기 게임 기획서

## 1. 프로젝트 개요

- 프로젝트명: 무지개 하트 벽돌깨기
- 목적: 자바스크립트의 키보드 입력, 애니메이션, 충돌 판정을 연습할 수 있는 웹 게임을 만든다.
- 실행 환경: 1024 × 768 해상도의 데스크톱 모니터와 최신 웹 브라우저에 맞춘다.
- 저장 위치: `myenv_vibe/02-bricks`

## 2. 제작 범위

이번 프로젝트에서는 아래 파일을 서로 분리하여 작성한다.

- `brick_game.html`: 게임 화면의 구조
- `brick_game.css`: 배경색, 게임 영역, 글자 등 화면 꾸미기
- `brick_game.js`: 게임 시작, 조작, 이동, 충돌, 점수와 종료 처리

외부 서비스, 외부 이미지, 별도 프로그램 설치는 사용하지 않는다. 벽돌과 하트 등 모든 화면 요소는 HTML, CSS, 자바스크립트로 표현한다.

## 3. 확정 화면 사양

### 3.1 전체 화면

- 1024 × 768 모니터에서 스크롤 없이 주요 게임 화면이 보이도록 구성한다.
- 웹페이지의 배경은 흰색으로 한다.
- 게임 영역은 화면 가운데에 배치한다.
- 게임 영역의 권장 크기는 **960px × 700px**로 한다.
- 게임 영역의 경계가 보이도록 얇은 테두리를 표시한다.
- 화면 위쪽에는 게임 제목, 점수, 남은 목숨을 표시한다.
- 게임 시작 전에는 `스페이스키를 눌러 시작하세요`라는 안내 문구를 표시한다.

### 3.2 벽돌

- 벽돌은 **7개 층(7행)**으로 배치한다.
- 한 층에는 **9개**를 배치하여 총 **63개**의 벽돌을 사용한다.
- 벽돌 하나의 크기는 **너비 100px × 높이 36px**로 한다.
- 요청의 `100px`은 화면 높이 안에 7층과 게임 공간을 함께 넣을 수 있도록 **너비 기준**으로 해석한다.
- 벽돌 사이에는 충돌 구분이 보이도록 작은 간격을 둔다.
- 색상은 빨강, 주황, 노랑, 초록, 파랑, 남색, 보라를 각 층에 섞어서 사용한다.
- 각 벽돌 가운데에 하트(`♥`)를 표시한다.
- 하트는 벽돌과 명확히 구분되는 색으로 한다. 밝은 벽돌에는 검정 계열, 어두운 벽돌에는 흰색을 사용한다.
- 공에 맞은 벽돌은 즉시 사라지고 점수에 반영한다.

### 3.3 공과 사용자 조작 바

- 사용자 조작 바의 크기는 **너비 150px × 높이 16px**로 한다.
- 사용자 조작 바의 색은 검정색으로 한다.
- 공은 잘 보이는 단색 원으로 표현하며, 지름은 **16px**로 한다.
- 게임 시작 전 공은 조작 바 위에 멈춰 있고, 조작 바를 움직이면 함께 이동한다.
- 조작 바와 공은 게임 영역 밖으로 나갈 수 없다.

## 4. 게임 조작 방법

- `스페이스키`: 처음 누르면 공이 움직이며 게임이 시작된다.
- `왼쪽 방향키(←)` 또는 `A`: 조작 바를 왼쪽으로 이동한다.
- `오른쪽 방향키(→)` 또는 `D`: 조작 바를 오른쪽으로 이동한다.
- 게임 종료 후 `스페이스키`: 게임을 처음 상태로 다시 시작한다.
- 방향키를 눌렀을 때 웹페이지가 움직이지 않도록 기본 스크롤 동작을 막는다.

## 5. 게임 진행 규칙

1. 처음 화면에는 벽돌 63개, 조작 바, 공, 점수, 남은 목숨을 표시한다.
2. 사용자가 스페이스키를 누르기 전까지 게임은 시작되지 않는다.
3. 게임이 시작되면 공은 대각선 위쪽으로 이동한다.
4. 공이 게임 영역의 왼쪽, 오른쪽, 위쪽 벽에 닿으면 반사된다.
5. 공이 조작 바에 닿으면 위쪽으로 반사된다. 조작 바의 어느 위치에 맞았는지에 따라 공의 좌우 방향이 달라진다.
6. 공이 벽돌에 닿으면 해당 벽돌이 사라지고 **10점**을 얻는다.
7. 공이 화면 아래로 떨어지면 목숨이 1개 줄어든다.
8. 시작 목숨은 **3개**로 한다. 목숨이 남아 있으면 공과 조작 바를 시작 위치로 되돌리고 스페이스키 입력을 기다린다.
9. 모든 벽돌을 없애면 `게임 성공!`과 최종 점수를 표시한다.
10. 목숨을 모두 잃으면 `게임 오버`와 최종 점수를 표시한다.
11. 성공 또는 게임 오버 뒤 스페이스키를 누르면 벽돌, 점수, 목숨을 모두 초기화하고 다시 시작한다.

## 6. 구현 방법

- 게임 화면은 HTML의 `canvas` 요소 하나를 중심으로 구현한다.
- 화면 갱신에는 `requestAnimationFrame`을 사용하여 움직임을 부드럽게 표현한다.
- 자바스크립트에서 다음 상태를 관리한다.
  - 게임 시작 전, 진행 중, 목숨을 잃은 대기 상태, 성공, 게임 오버
  - 공의 위치와 이동 방향
  - 조작 바의 위치와 이동 상태
  - 각 벽돌의 위치, 색상, 제거 여부
  - 점수와 남은 목숨
- 충돌 판정은 공과 벽, 조작 바, 벽돌의 위치를 비교하여 처리한다.
- 초보자가 읽기 쉽도록 함수의 역할을 작게 나누고 코드 주석과 변수 이름은 이해하기 쉬운 한국어 설명을 덧붙인다.

## 7. 예외 및 안전 처리

- 스페이스키를 여러 번 눌러도 공이 중복으로 출발하지 않게 한다.
- 왼쪽 키와 오른쪽 키를 동시에 누르면 조작 바가 갑자기 움직이지 않게 한다.
- 공이 벽돌 모서리에 닿아 한 번에 여러 벽돌이 비정상적으로 사라지는 현상을 줄인다.
- 브라우저 창의 크기가 1024 × 768보다 작으면 게임 전체가 비율에 맞게 축소되어 보이도록 한다.
- 실제 개인정보, 비밀키, 외부 데이터는 사용하지 않는다.

## 8. 파일별 제작 내용

### `brick_game.html`

- 문서 제목과 기본 안내 문구를 작성한다.
- `brick_game.css`와 `brick_game.js`를 연결한다.
- 게임을 그릴 `canvas` 요소를 만든다.

### `brick_game.css`

- 흰색 배경과 화면 가운데 정렬을 적용한다.
- 1024 × 768 화면에 맞는 여백과 게임 영역 크기를 설정한다.
- 작은 화면에서 비율에 맞게 보이는 반응형 규칙을 추가한다.

### `brick_game.js`

- 벽돌 7층과 하트 모양을 그린다.
- 키보드 입력과 조작 바 이동을 처리한다.
- 공 이동과 충돌 판정을 구현한다.
- 점수, 목숨, 성공, 게임 오버, 재시작을 처리한다.

## 9. 제작 단계

1. HTML로 게임 화면의 기본 구조를 만든다.
2. CSS로 1024 × 768 화면에 맞춰 배치한다.
3. 자바스크립트로 벽돌, 하트, 공, 조작 바를 그린다.
4. 스페이스키 시작과 방향키 조작을 구현한다.
5. 벽, 조작 바, 벽돌의 충돌 판정을 구현한다.
6. 점수, 목숨, 성공, 게임 오버, 재시작을 구현한다.
7. 완료 기준을 실제 브라우저에서 확인한다.

## 11. 제작 전에 확인하면 좋은 선택 사항

현재 기획서는 아래 항목을 기본값으로 정해 두었다. 원하는 방식이 다르면 프로그램 제작 전에 변경한다.

1. `벽돌 크기 100px`을 **너비 100px**로 해석하고 높이는 36px로 정했다. 가로와 세로 모두 100px을 원하면 게임 영역 배치를 다시 조정해야 한다.
2. 벽돌은 한 층에 9개, 총 63개로 정했다.
3. 키보드는 방향키뿐 아니라 A/D 키도 함께 지원하도록 정했다.
4. 시작 목숨은 3개, 벽돌 하나당 점수는 10점으로 정했다.
5. 소리, 여러 단계, 최고 점수 저장, 모바일 터치 조작은 이번 제작 범위에서 제외했다.
